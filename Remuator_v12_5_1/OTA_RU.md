# Загрузка Remuator 12.5.1 по Wi-Fi (Arduino OTA)

В прошивке включено Arduino OTA. Имя сетевого устройства: `remuator-s3`, порт: `3232`.
Встроенный пароль: `123456789A+-` (включая последние знаки «+» и «-»).

## Если передача обрывается с WinError 10054

Эта ошибка означает принудительный разрыв TCP-соединения во время передачи. Успешные строки `Authenticating ... OK` подтверждают, что пароль принят; они не объясняют причину последующего обрыва. По одному проценту загрузки нельзя отличить перезапуск ESP32, потерю Wi-Fi, питание или вмешательство сетевого ПО.

В 12.5 обнаружено неограниченное ожидание мьютекса в HTTP-обработчиках во время блокирующего ArduinoOTA.handle(). Открытая панель или файловый менеджер могут заблокировать задачу AsyncTCP и привести к watchdog-перезапуску. В 12.5.1 HTTP-запросы получают 503 при OTA/занятости за ограниченное время; сетевой обработчик не ждёт завершения всей прошивки. Это исправление возможной программной причины, а не подтверждение причины конкретного аппаратного обрыва.

Для обновления устройства, на котором пока стоит 12.5 или более старая версия:

1. Нажмите «Стоп», завершите калибровку/ручной тест и дождитесь неподвижных осей.
2. Закройте все страницы контроллера и менеджера на компьютере, телефонах и других устройствах. Это прекращает фоновые HTTP-запросы.
3. Повторите OTA штатным загрузчиком из выбранного пакета плат ESP32. Ваш `espota.exe` из 3.3.12 уже успешно проходит авторизацию; подменять его старым скриптом из другого пакета не нужно.
4. Если передача всё равно обрывается, установите 12.5.1 один раз по USB с прежним partitions.csv и без стирания всей Flash. Исправление должно попасть в работающую прошивку, чтобы повлиять на следующую OTA-передачу.
5. При повторении ошибки посмотрите USB Serial именно в момент обрыва. `task_wdt`/watchdog указывает на зависшую задачу, `Brownout` — на просадку питания, `Guru Meditation`/panic — на программный сбой. Без перезапуска проверяйте Wi-Fi и сетевое ПО компьютера.

В 12.5.1 доступен `http://АДРЕС/api/ota`: статус работает без мьютекса управления, в том числе во время передачи. Поля `received`/`total` показывают передачу, `otaError` — код ArduinoOTA (-1 означает отсутствие ошибки), `flashError` — код Update, `resetReason` — причину последнего запуска ESP32, `nextSlotBytes` — размер реального раздела назначения. Эти диагностические данные хранятся в RAM до перезапуска; причина перезапуска относится к текущей загрузке, а не является доказательством связи с OTA.

Коды `otaError`: 0 — авторизация, 1 — начало записи, 2 — обратное соединение с компьютером, 3 — приём данных, 4 — завершение/проверка образа. При ошибке в Serial выводятся также код и текст Update. Для кратковременных сетевых задержек тайм-аут приёма увеличен до 5 с; энергосбережение Wi-Fi выключается на время попытки и восстанавливается при ошибке.

Сообщение Arduino IDE «Всего доступно 16777216 байт» относится к выбранному общему лимиту Flash и само по себе не подтверждает размер раздела OTA. Для исходного partitions.csv каждый слот приложения — 4194304 байта, LittleFS — 1048576 байт. Бинарный файл около 1,4 МБ помещается в такой слот. Не меняйте таблицу разделов наугад и не пытайтесь обновлять её через OTA. Отсутствие или недостаточный размер слота обычно выявляется в начале записи, а не случайно на 35%.

## Первая установка

Если на контроллере ещё нет работающего OTA, установите эту версию один раз через USB.
Откройте `Remuator_v12_5_1/Remuator_v12_5_1.ino` в Arduino IDE. Сохраните настройки своей ESP32-S3,
размер Flash 16 MB и используемый режим PSRAM; в проверенной сборке выбран OPI PSRAM.
Используйте имеющийся `partitions.csv` из папки скетча: два раздела приложения по 4 MB и LittleFS 1 MB.
Не выбирайте стирание всей Flash: там находятся программы, калибровки и журналы.
Смена таблицы разделов через OTA не поддерживается; её первоначальная установка выполняется по USB.

## Обновление из Arduino IDE

1. Остановите программу кнопкой «Стоп». Дождитесь полной остановки обоих двигателей и завершения калибровки/ручного теста. Пауза выполняющейся программы для OTA недостаточна.
2. Подключите компьютер и контроллер к одной сети Wi-Fi. Можно подключить компьютер непосредственно к точке доступа контроллера `RemuageVRN` (заводской пароль `43214321`, адрес `192.168.4.1`). Для домашней сети используйте фактический адрес контроллера, показанный в настройках сети.
3. В Arduino IDE откройте скетч, выберите свою плату ESP32-S3 и прежние параметры сборки. В меню «Инструменты → Порт» выберите сетевой порт `remuator-s3` / `remuator-s3.local` с адресом контроллера.
4. Нажмите «Загрузить». При запросе пароля введите `123456789A+-`.
5. Дождитесь успешного окончания передачи и перезагрузки. Откройте главную страницу и проверьте версию `12.5.1` внизу страницы.

Если сетевого порта нет, проверьте, что программа остановлена, компьютер находится в той же подсети и между устройствами нет изоляции клиентов Wi-Fi. Разрешите Arduino IDE/Python в брандмауэре частной сети. Для обнаружения имени используется mDNS (UDP 5353), для OTA — порт 3232 и обратное TCP-соединение к компьютеру. В настройках «Serial» после загрузки системы должна быть строка `OTA ready on port 3232`.

## Передача по IP без обнаружения сетевого порта

В Arduino IDE выберите «Скетч → Экспорт скомпилированного бинарного файла».
Для обновления приложения нужен **`Remuator_v12_5_1.ino.bin`**. Не используйте `.merged.bin`, `.bootloader.bin`, `.partitions.bin` или образ LittleFS.
Используйте штатный загрузчик из той же версии пакета ESP32, которая выбрана в Arduino IDE. В пакете 3.3.12 из вашего журнала это `espota.exe`; в старых пакетах мог использоваться `espota.py`.

Пример для Windows CMD с ESP32 3.3.12 (замените путь к BIN и IP на свои):

```bat
"%LOCALAPPDATA%\Arduino15\packages\esp32\hardware\esp32\3.3.12\tools\espota.exe" -r -i 192.168.4.1 -p 3232 "--auth=123456789A+-" -f "S:\путь\Remuator_v12_5_1.ino.bin"
```

В PowerShell:

```powershell
& "$env:LOCALAPPDATA\Arduino15\packages\esp32\hardware\esp32\3.3.12\tools\espota.exe" -r -i 192.168.4.1 -p 3232 "--auth=123456789A+-" -f "S:\путь\Remuator_v12_5_1.ino.bin"
```

Для домашней сети укажите её фактический IP контроллера вместо 192.168.4.1. Не подменяйте загрузчик сторонним файлом от другой версии пакета.

Если компьютер имеет несколько сетевых интерфейсов, скрипту можно добавить `-I IP_КОМПЬЮТЕРА_В_ЭТОЙ_СЕТИ`.
Не отключайте питание во время передачи. При ошибке проверьте связь и повторите загрузку при остановленном контроллере.

## Обновление страниц без удаления данных

OTA приложения обновляет прошивку, а веб-файлы остаются прежними. Для версии 12.5.1 обновите также страницы из папки `data`.
Остановите программу и откройте `http://АДРЕС_КОНТРОЛЛЕРА:8080/` (файловый менеджер, заводские реквизиты: `admin` / `2026`).
Загрузите файлы, расположенные непосредственно в `data`, в корень `/`, сохранив имена.
Каталог `data/prog` с примером программы повторно загружать не нужно.

Можно выполнить из папки скетча:

```powershell
py tools/upload_web.py http://192.168.4.1:8080
```

Скрипт спросит пароль файлового менеджера. Этот пароль отличается от пароля OTA.
Такое обновление не форматирует LittleFS и сохраняет `/prog`, `/state`, `/Logs`, `/settings` и файлы калибровки.
Не загружайте полный образ файловой системы поверх работающей установки: это заменит её содержимое.
После обновления страниц нажмите Ctrl+F5 в браузере.
